# Skill conventions for this repo

Grounded in the research under `docs/research/`. Rules marked (!) are enforced by `bin/check`.

## Layout
- One skill = `skills/<name>/SKILL.md` (+ `references/`, `scripts/`, `agents/openai.yaml`). (!) Nothing else may contain a `SKILL.md`: Codex registers every `SKILL.md` it finds, at any depth.
- `skills/<name>/agents/openai.yaml` is generated by `bin/build` from the frontmatter; commit it (Codex reads it from the repo). To override, write it by hand without the generated marker, or set `metadata.display-name` / `metadata.short-description` in the frontmatter.
- (!) No symlinks anywhere: Codex drops them when it caches the plugin.
- Shared material (procedures, templates, scripts used by several skills) lives in `shared/`, which is NOT a skill and never shows up in any skill list.

## Frontmatter (portable subset)
```yaml
---
name: my-skill                 # == directory name, a-z0-9 and hyphens, <= 64 chars (!)
description: >-                # <= 1024 chars (!); trigger words first - this is all the model sees before invoking
  ...
disable-model-invocation: true # command-like skill: only the user runs it (Claude, Cursor). Codex gets the equivalent via generated openai.yaml.
user-invocable: false          # model-only helper: hidden from `/` menu, model may invoke (Claude, Cursor CLI). Codex ignores.
---
```
Everything else (`allowed-tools`, `context: fork`, `agent`, `hooks`, `paths`, `argument-hint`) is Claude-only; Codex and Cursor ignore unknown fields, so it is safe but non-portable.

## Reusing a procedure from several skills
Do NOT create a "private skill" and ask the model to invoke it. Why:
- Codex and Cursor have no Skill tool - the model just reads a file. A hidden Codex skill is not even listed, so the parent would have to give the path anyway.
- In Claude Code, `Skill()` from inside a skill has open bugs (#17351 parent workflow stops, #56912 permission prompt) and `disable-model-invocation: true` blocks nested invocation entirely.

Instead:
1. Put the procedure in `shared/procedures/<x>.md` (checklist style, imperative, self-contained).
2. In the parent SKILL.md, near the top, write: `REQUIRED before step N: read ../../shared/procedures/<x>.md (path relative to this skill's directory) and follow it.` (!) The referenced file must exist.
   All three agents resolve paths relative to the skill directory: Claude Code prints `Base directory for this skill: ...`, Codex's prompt says to resolve relative to SKILL.md, Cursor documents relative paths from the skill root.
3. Keep references one hop deep (SKILL.md -> shared file). Never chain shared file -> another file.
4. Steps that must happen every time: inline them in the first ~100 lines of SKILL.md (Claude keeps only the first 5000 tokens of a skill after compaction), or use a hook (Claude: `hooks:` in frontmatter / plugin `hooks/hooks.json`). Prose is never deterministic.
5. Scripts shared by several skills: `shared/bin/<tool>`, invoked as `../../shared/bin/<tool>` relative to the skill directory. (!) `bin/check` warns about absolute `~/.claude/skills/...` style paths.

## Names across agents
The plugin is `euphotic`, so a skill `foo` is `/euphotic:foo` in Claude Code (bare `/foo` also works when no other command uses the name), `$euphotic:foo` in Codex, `/foo` in Cursor. Inside SKILL.md refer to sibling skills by bare name plus file path, never by the namespaced form.

## Size budget
Claude Code lists name+description of every skill within ~1% of the context window and silently drops descriptions of the least-used skills past that; Codex uses 2% (cap 10000 chars). Keep descriptions tight; `disable-model-invocation: true` skills do not consume the Claude budget, `user-invocable: false` ones do.
