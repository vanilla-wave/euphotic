# Skill conventions

Two different things live in this repo, and they should not be confused:

- **Principles** (`README.md`; in operative form, the `skill-creator` skill) are about the
  *content* of a skill - what it asks of the agent. They are deliberately loose: priorities and
  reference points, not rules.
- **Conventions** (this file; the items marked (!) are enforced by `bin/check`) are about *packaging*:
  what the three runtimes - Claude Code, Codex, Cursor - can and cannot load. These are mechanical,
  because a violation silently breaks one of the agents rather than making a skill slightly worse.

## Layout
- One skill = `skills/<name>/SKILL.md`, plus `references/`, `scripts/`, `agents/openai.yaml` as needed.
  (!) Nothing else in the repo may contain a `SKILL.md`: Codex registers every `SKILL.md` it finds, at any depth.
- `skills/<name>/agents/openai.yaml` is generated by `bin/build` from the frontmatter and committed
  (Codex reads it from the repo). To override, write it by hand without the generated marker, or set
  `metadata.display-name` / `metadata.short-description` in the frontmatter.
- (!) No symlinks anywhere: Codex drops them when it caches the plugin.
- Material used by several skills (procedures, templates, scripts) lives in `shared/`. It is not a
  skill and never shows up in any skill list.

## Frontmatter: the portable subset
```yaml
---
name: my-skill                 # (!) == directory name; a-z0-9 and hyphens; <= 64 chars
description: >-                # (!) <= 1024 chars; trigger words first - this is all the model sees before invoking
  ...
disable-model-invocation: true # command-like skill: only the user runs it (Claude, Cursor; Codex gets it via the generated openai.yaml)
user-invocable: false          # helper the model may invoke but the user does not see in the `/` menu (Claude, Cursor CLI; Codex ignores)
---
```
Everything else (`allowed-tools`, `context: fork`, `agent`, `hooks`, `paths`, `argument-hint`) is
Claude-only. Codex and Cursor ignore unknown fields, so it is safe to use, just not portable.

## Sharing a procedure between skills
Put it in `shared/` and tell the skill when to read it - a plain sentence, e.g.
"Before writing the plan, read `../../shared/procedures/review-checklist.md`." Paths are relative to
the skill directory: Claude Code prints `Base directory for this skill: ...` when it loads a skill,
Codex's prompt resolves paths relative to `SKILL.md`, Cursor documents paths relative to the skill root.
(!) The referenced file must exist.

Why a file and not a hidden "helper skill" the agent is told to invoke: Codex and Cursor have no
Skill tool - the model just reads a file, and a hidden Codex skill is not even listed, so the parent
would have to give the path anyway. In Claude Code, invoking a skill from inside a skill has open
bugs (#17351 parent workflow stops, #56912 permission prompt), and `disable-model-invocation: true`
blocks nested invocation entirely.

Two limits of the mechanism worth knowing: references stay one hop deep (SKILL.md -> shared file;
the agents read nested references only partially), and nothing in prose is deterministic - a step
that must happen every time belongs in the first lines of `SKILL.md` (Claude keeps only the first
~5000 tokens of a skill after context compaction) or in a hook, not in capital letters.

Scripts shared by several skills go in `shared/bin/` and are invoked as `../../shared/bin/<tool>`.
(!) `bin/check` warns about absolute `~/.claude/skills/...`-style paths: they do not survive packaging.

## Names across agents
The plugin is `euphotic`, so a skill `foo` is `/euphotic:foo` in Claude Code (bare `/foo` also works
when no other command uses the name), `$euphotic:foo` in Codex and `/foo` in Cursor. Inside a skill,
refer to a sibling skill by bare name plus file path, never by the namespaced form.

## Size budget
Claude Code shows the model name + description of every skill within ~1% of the context window and
silently drops descriptions of the least-used skills past that; Codex uses 2% (cap 10000 chars).
Keep descriptions tight. `disable-model-invocation: true` skills cost nothing in Claude's budget,
`user-invocable: false` ones do.
